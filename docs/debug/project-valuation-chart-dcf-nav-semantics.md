# Debug: Project valuation chart DCF/NAV series semantics

This note documents what is **actually plotted** in the project chart under:

- `FINANSIELLA NYCKELTAL OCH VÄRDERING`
- component: `ValueRangeSnapshotCard` in `mode="project"`

## 1) Exact plotted sources

### UI binding (project mode)
In `SingleStockDashboard`, the chart props are mapped as:

- `npvLow` ← `projectViewMetrics.list2.NPV_perShare`
- `npvHigh` ← `projectViewMetrics.list2.DCF_Target_discounted_perShare`
- `tpLow` ← `projectViewMetrics.list2.NAV_prodStart_perShare`
- `tpHigh` ← `projectViewMetrics.list2.DCF_perShare`
- `chartFlows` ← `snapshot.project.chartFlows`

### chartFlows backend generation
In `runCorporateSnapshotPipeline`, project chart flows are generated as:

- `snapshot.project.chartFlows.dcfProdstartPresentPerShareSeries`
- `snapshot.project.chartFlows.navProdstartPerShareSeries`

for `tp .. tp+5` by repeatedly calling `computeLista2CfDcfMetrics` at each hypothetical `tp_k`.

### Formula basis from Lista2
`computeLista2CfDcfMetrics` computes:

- `DCF_prodStart_exCapex` = discounted from `t >= tp` to **TP**.
- `DCF_prodStart_present` = `DCF_prodStart_exCapex * (1/(1+r)^tp)` = discounted to **TODAY**.
- `NAV_prodStart` = `NPV_prodStart + netCash_t0_post` where `NPV_prodStart = DCF_prodStart_exCapex - initialCapex(before tp)`.

## 2) What the chart stitches together

In project mode `ValueRangeSnapshotCard` currently builds series as:

1. index `0`: today anchors
   - NAV line value uses `npvLow` (`NPV_perShare`, today basis)
   - DCF line value uses `npvHigh` (`DCF_Target_discounted_perShare`, today basis)
2. indices `1 .. tp-1`: **synthetic interpolation** (not model output)
3. index `tp`: explicit TP anchors
   - NAV uses `tpLow` (`NAV_prodStart_perShare`, TP basis + netCash_t0)
   - DCF uses `tpHigh` (`DCF_perShare`, TP basis)
4. indices `tp+1 ..`: from `chartFlows`
   - DCF uses `dcfProdstartPresentPerShareSeries[k]` (today basis, rolling tp_k)
   - NAV uses `navProdstartPerShareSeries[k]` (TP_k basis + netCash_t0)

So the line is not one uniform model series: it is stitched from multiple definitions.

## 4) Definition-switch conclusion

Classification:

- **C + B together** in practice.
  - **C:** endpoint patch/interpolation before TP.
  - **B:** basis switch across TP (today-basis, TP-basis, then rolling today/TP_k mixed bases).

The chart does **not** use one consistent DCF/NAV definition across all x points.

## 5) Why DCF rises into TP then falls after TP

Given current construction:

- From today to TP, DCF is forced by interpolation from `DCF_Target_discounted_perShare` (today basis) up to `DCF_perShare` (TP basis), so it tends to rise.
- Immediately after TP, the plotted DCF switches to `dcfProdstartPresentPerShareSeries[k]` (today-discounted rolling tp_k), which is usually lower due to additional today-discounting and horizon effects at larger tp_k.

So the observed rise-then-fall is mostly explained by **series-definition mismatch / stitched bases**, not a single smooth formula behaving on one consistent basis.
